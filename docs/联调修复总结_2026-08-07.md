### 2. 你之前「打开 Expo Go 卡死」，很可能就是 SVG 这个坑
你反馈过 Android 端 Metro 打包成功、但 App 卡在启动画面进不去。**我们这次定位到宠物「SVG」资源其实是 3–4MB 的位图套壳（详见下方问题 6），一次性渲染会卡死主线程。** 这批资源在启动/渲染路径上到处都在用，很可能就是你卡死的元凶之一。

我们已经把它们全部换成压缩后的 PNG（49MB → 4.9MB）。**你拉到这个改动后，大概率你的启动卡死也会好。** 如果还卡，再一起看别的原因。

## 背景：为什么一开始连不上真实云端

`integrate/ai-travel-v3` 把 `USE_MOCK` 改成了读环境变量（`lib/supabase.ts`）：

```ts
export const USE_MOCK = process.env.EXPO_PUBLIC_USE_MOCK === 'true'
  || supabaseUrl.includes('mock.supabase.co');
```

但真实 URL / key 放在 `.env` 里，而 `.env` 被 `.gitignore` 忽略，**没进 git**。所以任何人 clone 下来，环境变量为空 → 回退到 `mock.supabase.co` → `USE_MOCK` 自动变 `true` → 全是假数据。

**解决**：在项目根目录建 `.env`（照 `.env.example`），填真实的：
```
EXPO_PUBLIC_SUPABASE_URL=https://ulrzilxhuuxxezhgrptg.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=<sudo-app 的 publishable key，sb_publishable_ 开头>
```
> 注意：Edge Functions 只认**新版 publishable key**（`sb_publishable_...`），旧版 anon JWT 会被函数鉴权拒绝（401）。数据库读写两种 key 都兼容，但为了让 AI 函数能用，`.env` 里统一用 publishable key。

## 注册流程踩的坑（数据库这边）

云端 `sudo-app` 项目当初只建了部分表 / 授权不全，注册时逐个暴露：

### 问题 1：`Could not find the 'pet_breed' column of 'profiles'`
- **根因**：App 代码是 v3.5，但云端数据库缺了迁移 56–61（`pet_breed` 列、宠物聊天表、漂流瓶表、匹配队列等都没建）。
- **解决**：把迁移 56–61 合并成一份幂等脚本，在 Supabase SQL Editor 执行。

### 问题 2：`permission denied for table profiles`
- **根因**：云端那张 `profiles` 表是简化手建版，缺整套列级授权（`GRANT`）和 RPC 函数。正规建表脚本（迁移 25）用的是列级精细授权 + 一堆 RPC。
- **解决**：把迁移 25–61 按序合并成完整重建脚本，一次性执行（会 drop 重建业务表，测试数据清空——联调阶段可接受）。

### 问题 3：`Save Failed - permission denied`（注册最后一步 Finish Setup）
- **根因**：注册提交时写了 `edu_verified` 字段，而该列是**只读保护**的（防止客户端自我认证教育邮箱），一写整条 update 被拒。
- **解决**：从 `OnboardingScreen.tsx` 的 `updateProfile({...})` 里**删掉 `edu_verified: isEduVerified` 这一行**。
- **⚠️ Ethan 注意**：你那边注册会撞同样的错，确认这行已删。

### 问题 4：`Save Failed - Not authenticated`
- **根因**：之前那个卡住的引导流程挂在已失效的会话上。
- **解决**：清掉本地会话，用新邮箱重新注册。（`signUp` 建议补一个 `data.session` 判空——目前只判了 `data.user`，会话为空时应提示。属于待改进项。）

## 「幽灵问题」：改了半天没生效

有一大段时间，我们改的东西（新 key、修复、日志）**在 App 里完全不生效、报错也传不出来**。

- **根因**：模拟器里的 Expo Go 一直在跑一份**过期缓存的 bundle**，和开发服务器的连接断了。
- **解决**：`npx expo start -c` 清 Metro 缓存 + **卸载重装 Expo Go**（清掉缓存的旧 bundle）+ 完整重新打包。之后跑的才是最新代码。
- **⚠️ Ethan 注意**：Android 上如果也遇到「改了不生效 / 迷之报错」，同样手法：`expo start -c` + 清 Expo Go 数据（长按图标 → App info → Clear data）。

## 宠物聊天「不回话」（AI 后端这边）

### 问题 5：宠物发消息没有任何反应
排查发现是三个独立 bug 叠加：

1. **AI 云函数根本没部署**。App 会 POST 到 `.../functions/v1/pet-chat`，但云端四个函数端点全是 404。
   - **解决**：用 Supabase CLI 部署了 `pet-chat`、`agent-chat`、`travel-mode` 三个函数。
   - 还配置了 Edge Function Secret `OPENAI_API_KEY`（函数用的是 OpenAI，不是 Anthropic——注意 `.env.example` 里写的 ANTHROPIC 和代码不一致）。
   - `whisper-stt`（语音转文字）仓库里**没有源码**，暂时跳过（语音功能先不做）。
   - 函数目录结构调整：`supabase/functions/index.ts` → `supabase/functions/pet-chat/index.ts`（CLI 部署要求每个函数独立文件夹）。

2. **入口接错线**：Inbox 里点 "zZuPer Talk" 被导航到了普通人聊页面（`Chat`），真正的 AI 聊天页 `PetChat` 在 App 里无路可达。之前发的消息全进了普通消息表，AI 从没被叫醒。
   - **解决**：`InboxScreen.tsx` 里把 `zzuper_talk` 的导航从 `navigate('Chat', {...})` 改成 `navigate('PetChat')`。

3. **React Native 的 fetch 不支持流式读取**：函数用 SSE 流式返回，但 RN 里 `response.body` 是 undefined，`getReader()` 拿不到，回复到了手机却显示不出来。
   - **解决**：`PetChatScreen.tsx` 里加了兜底——`reader` 为空时，把整段 SSE 文本一次性 `response.text()` 读出来解析，一次性显示宠物回复。

修完后宠物正常对话，抗提示词注入测试也通过（不会泄露 system prompt）。

## 测试中发现并修复的 3 个问题

### 问题 6：Profile 换装 / Closet「卡死」+「不灵」
这条其实是**两个**独立 bug：

**6a. 卡死** —— `assets/pets/` 里的 30 个「SVG」**根本不是矢量图**，而是把 1640×2360 的 PNG 位图用 base64 塞进 SVG 的 `<image>` 标签里（单个 3–4MB）。每次渲染 `react-native-svg` 都要解析这几 MB 的 base64，Closet 弹窗一次渲 3 个形态 + 页面头像，主线程直接卡死甚至 OOM。
- **解决**：写脚本把内嵌 PNG 全部抽出来、用 `sips` 缩到 600px（**49MB → 4.9MB**，单张 150–300KB，透明通道保留），改用原生 `<Image>` 渲染。删掉 30 个旧 `.svg`，新增 `assets/pets/png/*`，重写 `assets/pets/index.tsx`（`PetSvgAvatar` 组件对外签名不变，5 处调用无需改动）。
- **副作用（正向）**：Metro 打包模块数 1274 → 1162，启动更快。
- **对未来「装饰系统」的影响**：没有影响。换装（衣服/帽子/项链）靠的是**分层叠加**架构，跟底图是 PNG 还是 SVG 无关。而且这批资源本来就是位图套壳，从来没有真正的矢量能力。将来做可无级缩放/动态改色的装饰件时，单独为那些装饰件引入真 SVG 即可，两者能混着叠。

**6b. 宠物形态换装「不灵」** —— 点宠物形态没反应/存不进去。
- **根因**：`profiles` 表的列级 `GRANT UPDATE(...)` 清单里**漏了 `pet_stage`**（迁移 25 遗漏），所以 `updateProfile({pet_stage})` 被数据库以列权限不足拒绝。
- **解决**：补 `GRANT UPDATE(pet_stage) ON public.profiles TO authenticated;`（已应用到云端 + 新建迁移文件 `62_grant_pet_stage_update.sql`）。实测切 Youth 形态成功写库。

### 问题 7：没有明显的 Sign Out 按钮
- **根因**：Sign out 只是 Profile 页右上角一个光秃秃的图标，没文字、颜色浅，容易被忽略；而 Delete Account 是完整按钮，给人「只有 delete」的错觉。
- **解决**：在 Delete Account **上方**新增一个带图标+文字的 "Sign Out" 按钮（右上角图标保留）。

### 问题 8：找不到「好友请求」入口
- **根因**：通往 `FriendRequestsScreen` 的入口只在 Inbox 空状态出现，一旦有了好友/聊天就消失。
- **解决**：在 Inbox 右上角 `+` 下拉菜单里加常驻项 "Friend Requests"。
