## 0. 运维通知与 pg_net（起点）

| 事项 | 说明 |
|---|---|
| 安装 `pg_net` | 之前触发器里的 `net.http_post` 根本没有扩展支撑 |
| `verify_ops_key()` RPC | Edge Function 原来查 `vault.decrypted_secrets`，但 `vault` 不是暴露 schema，PostgREST 永远读到空 → 401。改成 RPC **只返回布尔值**，密钥一步不出库 |
| 删掉临时 selftest 函数 | 验证完即清 |

**装 pg_net 的意外收获**：Pulse 的 AI 只回一条就停，一直查不出原因。装完之后
`net._http_response` 第 11/12 行留下了证据——`Couldn't resolve host name`，时间戳正好压在
开场白上。根因是 `get_supabase_internal_url()` 返回 `http://kong:8000/...`。
**失败方式从「静默抛异常」变成「超时留下记录」**，这才查得到。（URL 本身还没修，是 Ethan 那侧的事。）

## 1. 身份 / 匿名模型（今天的主线设计）

方案讨论后定下的规则：

- **砍掉 S_A（`profile_visibility`）**——注册不再选，读取处也全部移除
- **宠物强制上主页**，完整展示（名字 + 品种 + 形态 + 将来的装饰）
- **匿名场景**（Pulse 接管前、群聊宠物发言）只给**裸形态**：品种 + 形态 + 会话内代号。
  无名字、无简介、无自定义头像、无装饰
- **Roam 是实名发帖**，宠物只是信使/风味角色
- **点头像进主页是全站原语**：宠物头像 → 裸宠物页（可举报/拉黑），真人头像 → 完整主页，自己 → 我的 Profile
- **过期的临时会话冻结（只读）**，不消失

已接受并需要在隐私政策里披露的威胁模型：裸形态 = 10 品种 × 3 形态 = **30 个桶**；
小群体足以击穿；A 方案下 `sender_id` 会经 Realtime 上线。

## 3. 今天修掉的 bug（按发现顺序）

1. **启动时闪一下 onboarding**——`!profile?.real_name` 把「还没加载」当成「新用户」，
   还有个 500ms 定时器强行清 loading。改成 `profileSettledFor` 门控导航。
2. **莫名其妙被登出**——`getProfile()` 网络失败返回 `null`，而 AuthContext 见 null 就登出。
   分开：**瞬时故障抛异常，确实不存在才返回 null**。
3. **拉黑列表空的**——我自己在 79 引入的。扫了 `from('profiles')`，
   漏了 PostgREST 内嵌联查 `blocked:profiles!...(...)`。`getTravelComments` 同一个毛病。
4. **拉黑对消息毫无作用**——旧问题，`blocked_users` 只被 `search_users` 用过。
5. **解除拉黑后，拉黑期间的消息全冒出来**——`blocked_users` 主键记不了区间，加 `block_periods`。
6. **未读角标和会话预览泄露被拉黑的内容**——同一个缺失过滤的第三、第四个出口。
7. **Pulse/Roam 报 `permission denied for table profiles`**——我漏掉的**第三类调用点**：
   RLS **策略表达式是以调用者身份求值的**，不像 SECURITY DEFINER 函数。策略里
   subquery 了 `profiles` 就跟客户端直查撞同一堵墙。已全库扫过，无残留。
8. **Clear chat history 要点一次 Cancel 才生效**——`LuxuryAlertModal` 的确认按钮
   **只调 `onConfirm`，从不调 `onClose`**。审了全部 4 个调用点，只有这处错。
9. **Roam 的 recall 点了没反应**——界面按 `now >= ends_at` 判断回没回来，
   而 recall 改的是 `status`，**故意不动 `ends_at`**。
10. **Pulse 会话退出再进变成普通私聊**——加 `is_agent_chat` 并据此路由。
11. **加好友点了没反应**——见下。
12. **加好友之后界面不升级**——见下。

## 4. 最后两个（今天收尾）

### 加好友发不出去

```js
from('conversation_members').select('account_id')   // RLS: auth.uid() = account_id
members.find(m => m.account_id !== myId)            // ← 恒为 undefined
```

只看得见自己那一行。而**它本来就不该拿得到**——Pulse 的匿名性就建立在
客户端没有对方 id 之上。所以改成按会话寻址（迁移 86）。

演练时又逼出一个：`source` 硬写了 `'pulse'`，被 `friendships_source_check` 打回。
**这个如果只看代码不跑，表现跟原 bug 一模一样**（点了没反应）。

### 加好友之后不升级

不是没升级，是**升级到别的会话去了**。`handle_friendship_update` 反查
`kind='petchat' and is_temporary` 然后 `limit 1`，**没有 order by**。
两人被匹配过不止一次时就是任取一个：

- 请求发自 `c92e08d8`（02:40 建，屏幕上那个）
- 触发器升级了 `e3615271`（02:35 建，早被删掉的旧会话）

数据全对、没报错、升级也确实发生了，只是发生在别处。修法：把会话记在关系上（迁移 88）。

**一个需要知道的副作用**：迁移 87 清掉 `is_agent_chat` 之后，Ethan 的
`trigger_agent_chat_reply` 第一句 `if is_agent_chat is not true then return` 会生效，
**加完好友 AI 就彻底不再替谁说话**。原来只有「双方都接管过」才停得下来。
他的函数一个字没动，这是数据变准带来的结果。

## 8. 回滚脚本

73–88 **全部有对应的 ROLLBACK 脚本**（补齐了原先缺的 81、83–88）。每个都写明了
回滚的代价，以及必须一起改回去的客户端文件。几条要注意的：

- **ROLLBACK_84 / 81 单独跑没有意义**——必须先 ROLLBACK_79。
  84 恢复的策略里有 `select profiles.university`，而策略表达式是以调用者身份求值的，
  79 之下必然 `permission denied`；81 删掉的两个 RPC，客户端只能退回内嵌联查，那条路在 79 之下是死的。
- **ROLLBACK_87 不可逆**：迁移 87 的 backfill 把已升级会话的 `is_agent_chat` 一律置 false，
  哪些原本是 true 没有留下记录。脚本里是按「存在宠物消息」近似还原。
- **ROLLBACK_83 会丢数据**：`block_periods` 表被删，历史拉黑区间不可恢复。

> ⚠️ 这些脚本**没有实际执行验证过**。函数体是从已成功应用的迁移里逐字取的
> （77 / 81 / 26 / 80 / 82），新写的只有 drop、alter table、84 的策略和 87 的近似 backfill。
> 真要回滚时先在分支上跑一遍。
